# Repository working agreement

## Scope and working method

Follow the current task's explicit scope and acceptance criteria within platform permissions. Preserve business, security, data, economic and release contracts; read applicable nested `AGENTS.md` before editing. Historical plans are context, not authority. Analysis-only and approval-before-edit tasks remain read-only until authorized.

Resolve mutable branch/SHA/PR/check facts from GitHub and inspect unknown local changes. Resume matching work. Read only relevant project/recovery notes, diffs and affected files; expand for uncertainty or impact and reuse unchanged context. Skills provide methods, not extra authorization, approval or stopping gates. Respect platform requirements without adding repeated confirmations, mandatory full workflows or ceremonial announcements. Prefer existing implementation/dependencies and the smallest sufficient change; plan material decisions, batch related edits, and parallelize only independent work with one writer per shared file, branch, runtime or evidence identity.

## Testing and verification

- Use risk-based, minimum sufficient verification based on changed behavior and real call paths. Do not enforce Superpowers TDD or fresh-verification-per-message workflows. Tests may precede or follow implementation; never delete working code solely because it preceded a test. For defects, prefer a minimal reproduction and necessary regression coverage; reuse existing tests and avoid redundant or brittle implementation-detail assertions.
- Start with failing cases and directly affected checks. Expand only for concrete cross-module risk, uncertain impact or explicit applicable acceptance. Neither each small edit nor each final delivery automatically requires all tools, the full suite or a complete backtest matrix. Batch related fixes; run expensive/full validation on a stable candidate only when impact or the delivery contract requires it.
- Reuse results while covered behavior/code, tests, dependencies, configuration, data and relevant environment remain equivalent; invalidate only affected evidence. Messages, handoffs, commits, pushes or new SHAs alone do not require reruns. Record the actual tested source and reuse scope; never present old CI results as a new HEAD's status. Actual required checks and explicit exact-revision acceptance still apply.
- Behavior-neutral documentation/comments need only relevant format, link, command or documentation-contract checks. Instruction edits also need ambiguity, duplication, conflict, authorization and completion-boundary review, not unrelated economic reruns. Executable configuration, generated inputs and parsed documentation are not automatically behavior-neutral. Money, order, risk, security or persistent-data changes need affected invariants and necessary integration/replay checks.
- Review the task diff once; repeat focused review after material changes. Reuse existing tests/logs, not a new verification framework. Report verified, reused, unrun and failed items with scope; a partial pass is not full acceptance. Never fabricate evidence, hide failures, weaken safety/data-integrity checks or frozen thresholds/fixtures, or bypass required reviews/checks and branch protection.

## Execution, Git and delivery

Continue safe authorized work without repeated requests to continue. Read to resolve factual ambiguity; ask only for a necessary decision that cannot be resolved safely. Authorization does not imply spending, live trading, credential/permission changes, irreversible actions, unrelated writes or scheduled-task changes.

Resume the matching branch/PR; new work uses a feature branch unless a direct default-branch update is explicitly authorized. Preserve any PR-only policy. Save coherent milestones, push authorized changes and verify remote SHA. Keep mutable recovery state in the existing PR, not permanent instructions; no empty bootstrap commits or routine process files/Issues are required. Without explicit authorization, do not reset, clean, rebase, force-push, rewrite history, delete branches/worktrees, discard unknown work or overwrite unrelated changes. Never commit secrets.

Diagnose failed checks/candidates and continue with evidence-supported corrections or bounded alternatives within scope and budget, preserving failures. Do not repeat trials that add no information; continue independent work past local blockers. Finish when applicable acceptance and actual required checks are satisfied, without marginal optimization afterward. A checkpoint or PR alone is not completion. If no safe authorized action remains, preserve recoverable progress and report completed, failed, blocked and unverified items; do not promise background completion.

## Git/GitHub transfer and preservation

Inspect object identities, sizes and outgoing paths first; select necessary files and reuse unchanged references rather than whole working directories. Prefer authorized native Git or file-aware programmatic transfer; when unavailable, use the authorized connector without extracting credentials or repeating a confirmed-failed transport. Keep large bodies, complete Base64, huge JSON, archives and full logs out of model/tool text and arguments. Chunking followed by one giant request is not a solution. Prefer file-to-file, selective/range reads and bounded excerpts; string-only connectors use small recoverable batches.

Required large originals still need preservation. Use supported resumable/deterministic multipart transport when necessary, recording order, offsets, raw/encoded lengths and hashes; verify byte-for-byte reconstruction and expected Git/LFS object identity where applicable. Separate blobs are not append operations; summaries/hashes are not backups. Keep large transfers bounded and serial, reuse a concise local/remote identity and status ledger, and inspect state after interruption before retrying. Verify final local bytes and remote tree/commit/ref or storage manifest, not merely a created blob. Report unpreserved originals and temporary-runtime loss risk while continuing independent work; never rewrite historical evidence.
